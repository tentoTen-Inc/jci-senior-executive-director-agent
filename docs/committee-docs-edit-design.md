# 委員会資料を LINE で編集する 詳細設計 v1.0

最終更新: 2026-10-24
前提: 予定の自然文操作 `docs/calendar-design.md` §5.2（確認してから反映する流れを踏襲）、ドライブの資料のナレッジ `docs/drive-knowledge-design.md`、AIモデルの選び方（`app/llm.py` の `TASK_MODELS`）

## 1. 目的
理事メンバーが専務AIに頼むだけで、担当委員会の資料（Google ドキュメント）を更新できるようにする。
例: 遠藤大介委員長が「地域の担い手を育てる委員会にしたいのでサマリーを更新して」と送ると、
サマリーのスローガン・現状分析・目指すべき状態などの案を作り、本人が確認したうえでドキュメントに書き込む。

## 2. 使える人と範囲
| 立場 | 更新できる委員会 |
|---|---|
| 理事長・専務理事 | すべての委員会 |
| 副理事長 | 担当する委員会（`Member.supervised_committees`） |
| 委員長（委員会の席が「委員長」） | 自分が所属する委員会（兼務を含む） |
| 上記以外（副委員長・委員・監事・直前理事長など） | なし（「資料の更新は理事メンバーのみ」と返す） |

- 「理事メンバー」＝理事長・副理事長・専務理事・直前理事長・委員長。直前理事長は担当委員会がないため、実際に更新できる委員会はない。
- 副理事長は委員会の「席」を持たないため、担当委員会を新しい項目 `supervised_committees` で持つ。席にすると委員会あての出欠依頼の対象が変わってしまうので分ける。組織図の取込（`data/roster-*.json`）で設定する。
- 個別トークだけで受け付ける。グループで頼まれたら「個別トークでお送りください」と返す（案や確認がグループに流れないように）。

## 3. 対象の資料
- 委員会フォルダ: `COMMITTEE_DOCS_FOLDER`（2027年度は `04-委員会`）の直下で、名前に委員会名を含むフォルダ（例: `03-組織未来推進委員会`）。委員会名・フォルダ名が変わっても名前で探す。
- その配下（サブフォルダを含む）の **Google ドキュメント**。スプレッドシート・スライド・PDF は対象外（v1）。
- 編集できるのは **表の「項目名｜内容」のセル** だけ（v1）。
  - 2列の表: 左が項目名、右が内容（サマリーのスローガン・現状分析・目指すべき状態・事業概要・事業手法、事業計画書の各欄）。
  - 見出し行のある表: 「行の見出し × 列の見出し」のセル（例: 年間スケジュールの「例会/事業 × 3月」）。
  - 見出しが「（参考）」で始まる行は読み取り専用（LOM日程など）。
  - 表題・メンバー名・表の形は変えない。本文の段落の書き換えは v2 で検討する。

## 4. 流れ
```
本人（個別トーク）「◯◯な委員会にしたいのでサマリーを更新して」
  └ 資料編集の依頼か判定（「サマリー・計画書・資料」等 × 「更新・書いて・直して」等の語があるときだけ）
       └ 権限: 理事メンバーでなければ断る／更新できる委員会がなければ断る
       └ 委員会と資料を決める（候補が複数なら文から AI が選ぶ。決まらなければボタンで聞き返す）
       └ ドキュメントを読み、項目と今の内容を取り出す（Docs API）
       └ AI が各項目の案を作る（依頼文・今の内容・ナレッジ検索の結果［昨年の資料・理事長所信など］）
       └ 確認メッセージ: 変更する項目ごとに「変更後」の要約＋［更新する］［やめる］
本人が［更新する］
  └ 権限を再確認 → 読んだときの版から変わっていなければ書き込む（requiredRevisionId）
       └ 変わっていたら書き込まず「他の人が編集したため、もう一度お送りください」
  └ 監査ログ（誰が・どの資料の・どの項目）→「更新しました」＋ドキュメントのリンク
```
- 確認は依頼した本人だけが押せる。30分で失効。二重押しで2回書き込まない（`calendar_intent` と同じ）。
- 元に戻すときは Google ドキュメントの「版の履歴」から戻せる（確認メッセージと完了メッセージに書く）。

## 5. 書き込み方
- 内容セルの中身（最後の改行を除く）を消して、新しい文を入れる。複数行は改行で段落に分ける。
- 元の文字の書式（太字・フォント・サイズ）を新しい文にも付け直す。段落の寄せ方はセルの書式を引き継ぐ。
- 1回の `documents.batchUpdate` で、後ろの位置から順に書き換える（前の書き換えで位置がずれないように）。
- AI が返した項目だけを変える。空の案や項目名が一致しない案は捨てる。

## 6. AI
- タスク `doc_edit`（`TASK_MODELS`）: **Gemini 2.5 Flash**、考える時間 1024 トークン。
  - LINE で返事を待たせるので速さを優先（Pro は 25〜32 秒かかる）。一方で文章の質も要るため、
    考える時間を少しだけ与える。件数は少ない。
- 入力: 依頼文、委員会名、資料名、項目ごとの今の内容、ナレッジ検索の結果（本人が見られる範囲）。
- 出力（JSON）: `edits: [{field, text}]`、`summary`（何をどう変えたかの一文）、`question`（依頼が曖昧なときの聞き返し）。
- 指示: 項目名は与えた一覧から選ぶ／読み取り専用の項目は変えない／JC の事業計画の文体で、根拠のない数値・固有名詞を作らない／
  依頼が「◯◯を足して」のように一部だけなら、他の項目は返さない。

## 7. 権限とセットアップ
- 書き込み用のサービスアカウント `doc-editor@jci-sed-agent.iam.gserviceaccount.com` を新設する（読み取り用の `drive-reader` とは分ける）。
  - スコープ: `documents`（書き込み）と `drive.readonly`（フォルダの一覧）。
  - Cloud Run の実行SA（app-runtime）に、このSAの「トークン作成者」を付与（`scripts/setup_doc_editor.sh`）。
- ドライブ側: `04-委員会` フォルダだけを `doc-editor` に **編集者** で共有する（他のフォルダは書き換えられない）。
- 環境変数: `COMMITTEE_DOCS_FOLDER`（`04-委員会` のフォルダID）。未設定なら機能は無効（依頼には「未設定」と返す）。

## 8. データ
- `pendingDocEdits/{op_id}`: `member_id`・`committee`・`doc_id`・`doc_title`・`revision_id`・`edits`（項目と新しい文）・`summary`・`created_at`・`expires_at`・`status`（pending/done/declined/expired）。
- 監査ログ `doc.edit`（target=doc_id、detail=委員会名・項目名）。

## 9. フェーズ
| フェーズ | 内容 |
|---|---|
| P1 | 権限（理事判定・担当委員会・`supervised_committees`）、委員会フォルダと資料の探索、ドキュメントの項目の読み取りと書き込み（`app/committee_docs.py`）、セットアップスクリプト |
| P2 | LINE の依頼の判定・AI の案・確認と反映（`app/doc_edit_intent.py`）、`doc_edit` タスク |

## 10. テスト
- 権限: 理事長・専務は全委員会、副理事長は担当のみ、委員長は所属のみ、副委員長・委員・監事は不可。
- 項目の読み取り: 2列の表・見出し付きの表・「（参考）」行の除外（実際のサマリーの構造をもとにした fixture）。
- 書き込み: 後ろから順に削除と挿入、書式の付け直し、requiredRevisionId。
- LINE: グループでは断る、確認は本人のみ・期限切れ・二重押し、版が変わっていたら書き込まない。
